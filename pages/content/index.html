Make a MicroPython device observable. Record what a device is doing, how long it takes, and what goes wrong using a compact API for traces, logs, and metrics. The package installs as otel and exports JSON over HTTP to an OpenTelemetry-compatible receiver.

Traces

Follow an operation through nested spans, events, and connected services.

Logs

Send structured messages with severity and the current trace identifiers.

Metrics

Track counts, current values, and aggregate measurements over time.

Project objective

Give embedded applications a useful subset of OpenTelemetry concepts without requiring the full Python SDK. Instrument a sensor loop, robot command, or network transaction and correlate it with the rest of your system.

MicroPython device → Processors + exporters → HTTP receiver → Your backend

The receiver and observability backend run separately. This repository supplies the device SDK; it does not include a collector, dashboard, or storage service.

Your path through the docs

  1. Install and send telemetry from a network-connected board.
  2. Configure your deployment: service identity, endpoints, timeouts, and export queues.
  3. Instrument your application and carry context between components.
  4. Understand runtime behavior, then consult the API reference.

Scope and constraints

This is a compact implementation, not a complete OpenTelemetry SDK. It includes HTTP JSON export, explicit metric collection, optional threaded queues for spans and logs, and basic trace-context helpers. It has no gRPC exporter, automatic instrumentation framework, periodic metric scheduler, or durable telemetry queue.

Plan for your device budget. Queue sizes bound queued entries, but span history and distinct metric attribute combinations can continue to grow. Read memory and concurrency before using it in a long-running application.

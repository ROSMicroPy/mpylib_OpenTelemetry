1. Prepare the device and receiver

  • A MicroPython board with a working network connection and enough free heap for JSON payloads.
  • mip for installation and a requests module importable as urequests, supporting get, post, request, and the timeout argument.
  • An HTTP receiver reachable from the board with traces, logs, and metrics routes, conventionally on port 4318.
  • A synchronized clock. Configure the board RTC or run ntptime.settime() after network setup and before creating telemetry.

Connect Wi-Fi or Ethernet using your board's normal setup. The SDK does not configure networking. Use your receiver's IP address or a hostname that the board can resolve; localhost on the board means the board itself.

2. Install the package

Run this in the device REPL. MicroPython mip reads the package manifest, which maps the repository's src/ files into the otel package:

import mip
mip.install("github:ROSMicroPy/mpylib_OpenTelemetry", version="main")
import otel

For reproducible deployments, replace main with a tested commit or release ref. The repository's package.json is a MicroPython mip manifest, not an npm dependency file. If mip is unavailable, copy all files from src/ to /lib/otel/ on the device, including __init__.py.

If importing urequests fails, install a requests implementation compatible with your firmware before continuing. The HTTP code's urllib fallback is intended for CPython environments.

3. Send all three signals

Replace the example address with your receiver. Run after network and clock setup:

from otel import setup_otlp, get_tracer, get_logger, get_meter

setup = setup_otlp(
    endpoint="http://192.168.1.100:4318",
    service_name="sensor-node",
    resource={"device.id": "esp32-01"},
)

if setup["enabled"]:
    tracer = get_tracer("sensor-loop")
    logger = get_logger("sensor-loop")
    meter = get_meter("sensor-loop")
    samples = meter.create_counter("sensor.samples", unit="1")
    temperature = meter.create_gauge("sensor.temperature", unit="Cel")

    with tracer.start_as_current_span("sample") as span:
        span.set_attribute("sensor.name", "ambient")
        samples.add(1)
        temperature.set(23.5)
        logger.info("sample complete", {"temperature": 23.5})
        span.set_status("OK")

    status = setup["metric_reader"].collect()
    print("Metric HTTP status:", status)
else:
    print("Receiver unavailable; telemetry is disabled")

Expected behavior: the root span exports when the with block ends; the log exports when emitted; metrics export only when collect() is called. The log includes the active span's trace and span IDs.

4. Verify reception

  1. Check that setup["enabled"] is true. Setup probes the base endpoint using HTTP GET.
  2. Check receiver ingestion logs for POSTs to /v1/traces, /v1/logs, and /v1/metrics.
  3. In your backend, select service sensor-node and the current time range. Look for span sample, log sample complete, and metric sensor.samples.

A successful probe establishes reachability only. Even an HTTP error response can pass the probe. Confirm the POST endpoints accept the payloads; a nonzero returned status does not necessarily mean success.

Adapt the example

Create instruments once and update them in your application loop. Schedule metric collection at a rate your device and network can afford. The repository example also demonstrates NTP and HTTP instrumentation; its wifi import and receiver address are environment-specific.

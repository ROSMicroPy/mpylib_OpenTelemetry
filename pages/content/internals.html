Processor semantics

Queue sizes, batch sizes, and worker intervals are clamped to at least one. Entries retain their resource dictionary reference and their original records. Avoid mutating a span or log after queueing it. Requeue overflow retains the front of the merged queue and increments dropped_count.

snapshot() on queued processors reports queue length/capacity, batch size, interval, dropped count, and worker state. flush() drains until no entries remain. It has no timeout: queued span failures that keep requeueing can make it loop indefinitely. shutdown() requests worker exit and flushes but does not join the worker. There is no persistent spool or guaranteed delivery.

Simple span shutdown exports pending spans without their original resource argument. Prefer completing root spans normally so the usual export path supplies the provider resource.

HTTP JSON payloads

Exporters group records under resource and instrumentation-scope envelopes: resourceSpans/scopeSpans, resourceLogs/scopeLogs, and resourceMetrics/scopeMetrics. They POST JSON with Content-Type: application/json.

  • Trace and span IDs are hexadecimal strings. Unix nanosecond timestamps and integer attribute values are encoded as strings.
  • Attributes support strings, booleans, integers, floats, arrays, and dictionaries. None becomes an empty string value.
  • Counter and up/down counter sums use cumulative temporality; counters are marked monotonic.
  • Histograms export one unbounded bucket, no explicit bounds, plus count, sum, min, and max. They cannot provide a meaningful bucket-based percentile distribution.
  • Exported spans always use kind 1 (internal). The tracer's kind argument is stored as a span.kind attribute rather than changing the wire-level kind.

Reachability and failures

Startup probes use GET and accept any nonzero HTTP status as reachable. Exporters return a numeric HTTP status or 0 for failure/disabled telemetry. Processors check truthiness, so a returned 400 or 500 is treated as a completed export. Response bodies, including partial-success details, are not interpreted.

On the MicroPython requests path, detected timeouts disable telemetry globally; other request exceptions generally return zero. On the CPython fallback path, non-HTTP exceptions disable telemetry. Once disabled, queues are cleared during subsequent processing. A startup failure prints otel endpoint is down; recovery is application-controlled.

Memory and concurrency

  • TracerProvider retains every finished span dictionary in _finished_spans, even after successful export. snapshot() copies that list; no public pruning API exists.
  • Metric instruments retain one point per unique attribute set; collection does not reset or evict points. Repeated instrument creation also increases retained state.
  • Queues are bounded by entries, not payload size. Attributes, events, and JSON serialization can still consume substantial heap.
  • Queued processors use a lock when one is available. Current span context and metric updates are not isolated per thread or asynchronous task.

Measure heap use on your actual firmware and workload. The current span-history retention needs an application-specific lifecycle strategy or a library change for indefinite high-volume operation.

Timestamps and IDs

now_unix_nanos() detects ports whose epoch starts in 2000 and adds the Unix epoch offset. It uses time_ns() if available, otherwise scales time(); nanosecond units do not imply nanosecond clock resolution. Synchronize time before recording telemetry.

Span start/end, event, and log timestamps are recorded before export and preserved through queues. Metric data-point export timestamps are generated during serialization. IDs combine random 32-bit values; the implementation expects getrandbits() to be available.

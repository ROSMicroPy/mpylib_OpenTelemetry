No telemetry in the backend

  1. Confirm imports and network connectivity before setup. Test the receiver address from the device's network.
  2. Inspect setup["enabled"] and is_telemetry_enabled(). A timeout may disable all three signals.
  3. Inspect receiver logs and actual HTTP response codes. A reachable base endpoint does not prove that signal POST routes are correct.
  4. Check service.name and the backend's selected time range. An unsynchronized clock can put records far outside the current window.
  5. Confirm a root span ends, logs pass the severity filter, and the metric reader's collect() is called.

Common symptoms

ImportError: otelInstall from the manifest or copy the entire package to /lib/otel/. Restart the interpreter after updating files.

Unexpected timeout keywordYour requests implementation lacks the required timeout parameter. Use a compatible implementation for your firmware.

Enable exporter diagnostics

from otel.exporter import configure_debug

configure_debug(enabled=True, log_path="/otel_logs.txt")
# Reproduce one export, then turn logging off:
configure_debug(enabled=False)

Debug output records signal names, endpoints, payload byte counts, and statuses. Non-timeout export errors may also be written to stderr. Where environment variables are supported, OTEL_EXPORT_DEBUG=1 enables logging too; unset it to fully disable diagnostics. File-write errors are ignored. Limit diagnostic use to avoid unnecessary flash writes and check whether endpoint URLs contain sensitive values.

Recover after an outage

The SDK has no reconnect scheduler. Restore the network/receiver, shut down previous real providers if needed, run setup_otlp() again, and reacquire all application handles. Recreating providers starts new metric aggregates and does not recover dropped records. Calling enable_telemetry() alone will not replace no-op objects returned by failed setup.

Report a reproducible issue

Include your board, firmware version, library commit, setup parameters with secrets removed, actual processor types, relevant response codes, and a minimal example. For queue issues include snapshot() output; for memory issues include a measurement over a bounded run. Use the GitHub issue tracker.

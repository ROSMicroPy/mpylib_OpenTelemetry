Configure once at startup

setup_otlp() probes the receiver, creates providers and exporters, registers them globally, and returns their handles. Call it after the network and clock are ready, before obtaining your tracer, logger, and meter.

from otel import setup_otlp

setup = setup_otlp(
    endpoint="http://192.168.1.100:4318",
    service_name="robot-controller",
    resource={"device.id": "robot-01", "deployment.environment": "lab"},
    timeout_s=2,
    async_export=True,
    async_batch_size=16,
    async_queue_size=128,
    async_flush_interval_ms=200,
    log_level="INFO",
    probe_max_attempts=3,
    probe_retry_delay_s=1,
)

Use the returned handles

The result always includes enabled, resource, tracer_provider, logger_provider, meter_provider, and metric_reader. Successful setup also includes span_processor, log_processor, and async_export.

A failed probe disables telemetry and returns no-op providers and a no-op reader. Check enabled before accessing processor keys. The returned async_export flag reflects the request, not worker availability; a port without working _thread falls back to simple processors.

if setup["enabled"]:
    for name in ("span_processor", "log_processor"):
        processor = setup[name]
        if hasattr(processor, "snapshot"):
            print(name, processor.snapshot())
        else:
            print(name, "synchronous processor")

Control detail at runtime

from otel import set_log_level, set_trace_detail_mode

set_log_level("WARN")
set_trace_detail_mode("essential", essential_prefixes=("command.", "fault."))
# Return to all spans when diagnosing a problem:
set_trace_detail_mode("diagnostic")

Essential mode matches span-name prefixes. An empty prefix list allows all spans, even in essential mode. Invalid trace modes become diagnostic; invalid log levels become DEBUG. Passing no prefixes preserves the previous prefix list.

Handle failed log exports

from otel import set_log_fallback_handler

def local_log(record, resource=None):
    print(record.severity_text, record.body)

set_log_fallback_handler(local_log)

Fallback runs for a falsey export result while telemetry remains enabled. It does not run for every non-2xx response or when telemetry is globally disabled. Keep the handler small and do not send it back through the same telemetry logger.

Custom headers and manual setup

The convenience setup does not accept authentication headers. For a protected endpoint, construct exporters and providers explicitly; repeat the same pattern with LoggerProvider/SimpleLogProcessor and MeterProvider/MetricReader if you need the other signals.

from otel import (
    TracerProvider, SimpleSpanProcessor, HTTPSpanExporter,
    set_tracer_provider,
)

# Load this from your device's deployment configuration.
receiver_token = "replace-with-your-token"
provider = TracerProvider(resource={"service.name": "sensor-node"})
exporter = HTTPSpanExporter(
    endpoint="https://collector.example.com/v1/traces",
    headers={
        "Content-Type": "application/json",
        "Authorization": "Bearer " + receiver_token,
    },
    timeout_s=2,
)
provider.add_span_processor(SimpleSpanProcessor(exporter))
set_tracer_provider(provider)

Manual construction does not probe the endpoint or automatically enable previously disabled telemetry. Use HTTPS support and credential storage appropriate for your firmware.

Disable, recover, and shut down

disable_telemetry() gates emission; enable_telemetry() only flips that gate. There is no automatic reconnect loop. After a failed setup, restore connectivity and run setup again, then reacquire your tracer, logger, meter, and instruments. Existing no-op objects remain no-op.

Before replacing a successful setup, shut down its providers to avoid leaving old worker threads running. Collect final metrics before shutting down the meter provider. Provider shutdown() delegates to processors/readers; it does not turn off the global flag or join worker threads. Queued flush can block on repeated failures—see processor semantics.
